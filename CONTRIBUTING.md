# Участие в MicroUtils

## Ошибка или предложение

Создайте [Issue](https://github.com/AndZas/MicroUtils/issues/new/choose) и укажите утилиту,
её версию, версию Windows и шаги воспроизведения. Для идеи опишите задачу и ожидаемое поведение.
Не прикладывайте весь пользовательский профиль: журнал и скриншоты могут содержать имена устройств и локальные пути.

## Изменения кода

1. Обсудите заметное изменение в Issue.
2. Сделайте fork, создайте отдельную ветку и внесите изменение в папку нужной утилиты.
3. Выполните тесты, указанные в её документации разработчика.
4. Откройте Pull Request с описанием результата, ссылкой на Issue и выполненными проверками.

Релизные архивы, окружения, логи и пользовательские настройки не добавляются в PR.
Для интерфейса приложите скриншоты с демонстрационными данными.

## Новый проект

Добавьте отдельную папку в корень репозитория по образцу `SoundControl`, краткую строку
в основной README и собственную документацию. Папки проектов называют в PascalCase.
У каждой утилиты своя версия и теги с собственным префиксом.

Сохраняйте указания авторства и лицензии сторонних компонентов.
Вклад в исходники MicroUtils предлагается под MIT.
